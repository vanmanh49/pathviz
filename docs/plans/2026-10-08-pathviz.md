# PathViz Implementation Plan

Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build PathViz, a web app that visualises seven shortest-path
algorithms on an editable grid, with reversible step-by-step playback and
panels that explain each step.

**Architecture:** Algorithms are pure functions that return an ordered list of
step events. A framework-free playback engine replays those events into
typed-array state with periodic checkpoints, so any step is reachable in either
direction. React renders the grid once; a painter writes search state onto the
cell elements, and Zustand stores hold the grid, the runs and UI settings.

**Tech Stack:** React 18, TypeScript strict, Vite, Tailwind CSS v4, Framer
Motion, Zustand, lucide-react, Vitest, React Testing Library, ESLint, Prettier.

**Spec:** `docs/specs/2026-10-08-pathviz-design.md`

## Global Constraints

- React 18.x. TypeScript `strict: true`. No `any`; `no-explicit-any` is an error.
- Nothing under `src/algorithms/`, `src/generators/` or `src/engine/` imports
  React, a store or the DOM.
- A cell is `CellId = row * cols + col` everywhere.
- Neighbour order: N, E, S, W, NE, SE, SW, NW.
- Entering a cell costs its weight; a diagonal move costs weight × `Math.SQRT2`
  and needs both orthogonal cells open.
- Weights are 1–9 and 1 means plain. Start and end are never walls and always
  have weight 1.
- Checkpoint interval: `max(50, ceil(events.length / 200))`.
- Speeds: 0.25, 0.5, 1, 2, 5, 10, instant (`Infinity`). 1× is 60 events per second.
- Grid size: rows 5–40, columns 5–80. Defaults 25 × 50, 21 × 31 below 1024 px,
  21 × 15 below 640 px.
- Colours: the hex values in spec section 14.
- Library configuration (Tailwind v4, Vitest, ESLint flat config) is checked
  against current documentation before it is written.
- Every task ends with the gate `npm run lint && npm test && npm run build`,
  all three clean, followed by the browser check listed in the task.

## Review Focus

Conditions the spec implies but does not spell out, most likely first. Each
has a test in the task that owns the code.

1. **Anything that invalidates a run while it is playing** — a grid edit,
   resize, diagonal toggle, algorithm or heuristic change, a generator, or the
   compare toggle. Expected: the run is discarded, playback stops, every cell
   loses its search colour. (Tasks 4, 7, 8)
2. **Shortcuts while a control has focus.** Expected: Space on a focused
   button, select or input does only what that control does; arrows on the
   timeline or inside the grid do not also step; Ctrl+R still reloads. (Task 4)
3. **Playback at its bounds.** Expected: step back at 0 and step forward at
   the end do nothing; play at the end restarts from 0; seek clamps. (Task 4)
4. **Compare runs of unequal length.** Expected: the shorter run stays on its
   final state while the longer continues, and scrubbing back un-finishes it.
   (Task 8)
5. **Stored settings that are missing or corrupt.** Expected: the app renders
   with the dark theme and shows the tour. (Task 1)

```ts
interface PlaybackState { /* spec section 7; priority and h default to 0 */ }
createState(cellCount: number): PlaybackState
applyEvent(state: PlaybackState, event: StepEvent): void     // mutates, O(1)
checkpointInterval(length: number): number

  constructor(cellCount: number, events: StepEvent[]);
  readonly events: StepEvent[]; readonly state: PlaybackState;
```

`applyEvent` follows the table in spec section 5. `enqueue` on a cell that is

Behaviour the signatures do not settle:

- `run()` builds one `Run` per active pane, sets `index` 0 and starts playing;
  at instant speed it seeks to the end instead. `optimal` is
  `|pathCost − dijkstraCost| < 1e-9`, or `null` when there is no path.
- `length` is the longest run; each run is sought to `min(index, its length)`.
- `toggle()` runs when there is no run, restarts from 0 when at the end, and
  otherwise flips `playing`. Reaching the end sets `playing` false.
- The store subscribes to `useGridStore` and calls `clearRun()` when `grid`,
  `start`, `end` or `diagonal` change. `setAlgorithm`, `setHeuristic` and
  `setCompare` also clear it.
- The painter writes `data-state` = `frontier | visited | current | path` and
  removes it when none applies. Path cells also get `--i`, their position
  along the path, for the staggered trace.
- Shortcuts ignore events with Ctrl, Meta or Alt. Space is ignored on
  `button, input, select, textarea, a`. Arrows, Home and End are ignored on
  `input, select, textarea` and inside `[role="grid"]`. R is ignored in text
  fields. Handled keys call `preventDefault`.


Registry ids: `bfs`, `dfs`, `dijkstra`, `astar`, `greedy`, `bidirectional`,
`bellman-ford`. Octile is `max(dr, dc) + (√2 − 1) · min(dr, dc)`.

Decisions beyond spec section 6:

- DFS pushes neighbours in reverse order so it explores N first.
- A* orders its heap by `f`, then `h`, then insertion, and never re-opens a
  closed node. Every admissible heuristic here is also consistent, so that is
  still optimal.
- Greedy marks nodes discovered when it enqueues them.
- Bidirectional BFS strictly alternates sides, one level each. `found.node` is
  the cell where the searches met.
- Bellman-Ford scans cells in id order and emits `visit u` just before the
  first successful relaxation out of `u` in a pass.

## Appendix A: pseudocode and event lines

The registry stores each listing as one string per line. Events carry the
1-based line shown on the right.

**BFS**
```
1  queue ← [start]; dist[start] ← 0            relax start, enqueue start
2  while queue is not empty:
3    u ← queue.dequeue()                        visit
4    if u = goal: return path                   found, path
5    for each neighbor v of u:
6      if v was already discovered: skip        skip "already discovered"
7      dist[v] ← dist[u] + 1; parent[v] ← u     relax
8      queue.enqueue(v)                         enqueue
9  return no path                               noPath
```

**DFS**
```
1  stack ← [start]                              relax start, enqueue start
2  while stack is not empty:
3    u ← stack.pop()
4    if u was already visited: skip             skip "already visited"
5    mark u visited                             visit
6    if u = goal: return path                   found, path
7    for each neighbor v of u:
8      if v is not visited:                     skip "already visited" otherwise
9        parent[v] ← u; stack.push(v)           relax, enqueue
10 return no path                               noPath
```

**Dijkstra**
```
1  dist[start] ← 0; pq ← {start}                relax start, enqueue start
2  while pq is not empty:
3    u ← pq.extractMin()
4    if u was already settled: skip             skip "stale entry"
5    mark u settled                             visit
6    if u = goal: return path                   found, path
7    for each neighbor v of u not settled:      skip "already settled" otherwise
8      alt ← dist[u] + cost(u, v)
9      if alt < dist[v]:                        skip "no improvement" otherwise
10       dist[v] ← alt; parent[v] ← u           relax
11       pq.insert(v, alt)                      enqueue, priority alt
12 return no path                               noPath
```

**A\***
```
1  g[start] ← 0; open ← {start}, f = h(start)   relax start, enqueue start
2  while open is not empty:
3    u ← node in open with the lowest f
4    if u is already closed: skip               skip "stale entry"
5    close u                                    visit
6    if u = goal: return path                   found, path
7    for each neighbor v of u not closed:       skip "already closed" otherwise
8      alt ← g[u] + cost(u, v)
9      if alt < g[v]:                           skip "no improvement" otherwise
10       g[v] ← alt; parent[v] ← u              relax
11       open.insert(v, f = alt + h(v))         enqueue, priority f, h
12 return no path                               noPath
```

**Greedy best-first**
```
1  open ← {start}, priority h(start)            relax start, enqueue start
2  while open is not empty:
3    u ← node in open with the lowest h         visit
4    if u = goal: return path                   found, path
5    for each neighbor v of u:
6      if v was already discovered: skip        skip "already discovered"
7      parent[v] ← u                            relax
8      open.insert(v, h(v))                     enqueue, priority h, h
9  return no path                               noPath
```

**Bidirectional BFS**
```
1  queueA ← [start]; queueB ← [goal]            relax and enqueue both, with side
2  while both queues are not empty:
3    for each node u in this side's level:      visit
4      for each neighbor v of u:
5        if the other side reached v: note it   skip "reached by the other search"
6        else if this side has not seen v:      skip "already seen" otherwise
7          parent[v] ← u; enqueue v             relax, enqueue
8    if a meeting was noted: return the path    found, path
9    switch sides
10 return no path                               noPath
```

**Bellman-Ford**
```
1  dist[start] ← 0                              relax start
2  repeat up to |V| − 1 times:                  pass
3    for each cell u with a known distance:     visit
4      for each neighbor v of u:
5        if dist[u] + cost(u, v) < dist[v]:
6          dist[v] ← that sum; parent[v] ← u    relax
7    if nothing changed in this pass: stop
8  return path if dist[goal] is known           found and path, or noPath
```
